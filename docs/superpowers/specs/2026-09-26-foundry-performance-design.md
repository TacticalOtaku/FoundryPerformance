# Foundry Performance — быстрый клиент для Foundry VTT (дизайн)

Дата: 2026-09-26 · Статус: утверждён

Имена: продукт «Foundry Performance», идентификатор `com.nikif.foundryperformance`,
Rust-крейт `foundry_performance`, папки данных `FoundryPerformance`. «Пульт» — название
визуального направления интерфейса. В шапке панели: `FOUNDRY/PERFORMANCE`.

## 1. Цель и контекст

Друзья играют на тяжёлом сервере Foundry VTT **v14** через FLC (phenomen/flc). На RTX 5070 FPS
почти стабилен, на GTX 1060 — около 10. Foundry Performance — собственный клиент с той же базовой функцией
(список серверов → открыть игру в окне), но с упором на производительность. Код FLC не
используется.

Ключевой вывод анализа: FLC — тонкая обёртка Tauri над WebView2 (Chromium). FPS определяет
рендер Foundry (PIXI/WebGL) внутри движка, а не язык оболочки. Поэтому прирост достигается:
1. тюнингом движка (флаги Chromium) в отдельном окружении игрового окна;
2. агентом, внедряемым в страницу Foundry, который применяет профиль производительности.

**Критерий успеха:** на GTX 1060 при одной и той же тяжёлой сцене средний FPS и 1% low в Foundry Performance
(профиль «Баланс») заметно выше, чем во FLC, по встроенному «Замеру». Конкретный множитель
не обещается — измеряется.

### Объём v1
- Входит: список серверов (слоты), подключение, профили производительности, агент, HUD,
  «Замер», RU/EN, светлая/тёмная тема, трей.
- Не входит: запуск локального Node-сервера, импорт/экспорт, инкогнито, несколько игровых
  окон, автообновление (обновления раздаются вручную; в UI — номер версии), macOS/Linux.

## 2. Платформа и стек
- Только Windows 10/11 x64, WebView2 Evergreen.
- Tauri 2 (Rust) + Svelte 5 + TypeScript + Vite. Без UI-китов и CSS-фреймворков: свои
  компоненты, чистый CSS с токенами.
- Пакетный менеджер: npm (установлен). Rust toolchain ставится в рамках работ.
- Поставка: NSIS-установщик (per-user, без админа, загрузчик WebView2) + portable zip.

## 3. Архитектура

```
Лаунчер (окно Tauri, Svelte 5)       — WebView2 окружение №1, дефолтные флаги
   │ invoke(...)
Rust core                            — store, GPU-детект (DXGI), флаги, окна, трей, /api/status
   │
Игровое окно                         — WebView2 окружение №2 (свой data-dir, свои флаги)
   └ initialization_script = агент   — профиль сериализован в скрипт
```

### 3.1 Rust core — модули
| Модуль | Ответственность |
|---|---|
| `store` | JSON в `%APPDATA%\FoundryPerformance\` (`servers.json`, `settings.json`), версия схемы + миграции |
| `gpu` | DXGI: имя адаптера, VRAM, вендор → рекомендуемый профиль |
| `profile` | Профили + ручные правки → итоговый `ResolvedProfile` (чистая функция) |
| `engine_flags` | `ResolvedProfile` + расширенные настройки → строка аргументов Chromium (чистая функция) |
| `probe` | `GET {url}/api/status` с таймаутом 3 с → статус слота, версия Foundry |
| `windows` | Жизненный цикл окон: запуск игры закрывает лаунчер, закрытие игры открывает лаунчер |
| `tray` | Иконка трея: профиль, показать HUD, вернуться в лаунчер, выход |
| `telemetry` | Приём итогов сессии/«Замера» от агента, запись в `stats.json` по серверу |

### 3.2 Два окружения WebView2
Флаги Chromium применяются к процессу браузера целиком, поэтому игровое окно создаётся с
отдельной `data_directory` (`%LOCALAPPDATA%\FoundryPerformance\engine\`) и `additional_browser_args`.
Смена ANGLE-бэкенда = пересоздание игрового окна, лаунчер не перезапускается. Отдельный
data-dir также сохраняет HTTP-кэш ассетов и логины Foundry между сессиями.

### 3.3 Флаги движка игрового окна
По умолчанию (переопределяются в «Расширенных»):
- `--use-angle=d3d11` (выбор: d3d11 / d3d11on12 / vulkan / gl)
- `--enable-gpu-rasterization`, `--enable-zero-copy`, `--ignore-gpu-blocklist`
- `--force-high-performance-gpu`
- `--disable-renderer-backgrounding`
- `--disk-cache-size=2147483648`
- `--js-flags=--max-old-space-size=4096`
- для совместимости с серверами по http/локальным IP: `--allow-insecure-localhost`,
  `--allow-running-insecure-content`

Список проверяется на реальном WebView2 в ходе реализации (`chrome://gpu` в devtools
игрового окна); неработающие/вредные флаги удаляются.

### 3.4 Безопасность
- Удалённой странице Foundry **не** выдаются capabilities Tauri: команды приложения ей
  недоступны.
- Агент передаёт данные наружу только через один узкий канал (телеметрия: числа FPS,
  итог «Замера»), реализованный как единственная разрешённая команда с валидацией
  схемы на стороне Rust. Если безопасно выдать одну команду удалённому origin средствами
  Tauri 2 нельзя — телеметрия отключается, HUD работает локально.

## 4. Агент производительности

Один JS-файл (TypeScript → бандл), внедряется как `initialization_script` с
предпрописанным `window.__PULT__ = { profile, locale, safeMode }`. Выполняется на каждой
загрузке страницы в игровом окне. Фаза 1 (localStorage) выполняется всегда — она безвредна
для не-игровых страниц. Фазы 2–4 и HUD активируются, только когда загружен игровой клиент
Foundry (срабатывает хук `init`); на страницах `/join` и `/setup` агент ничего не рисует.

### 4.1 Фазы
1. **До загрузки Foundry:** запись client settings в `localStorage` (ключи вида
   `core.<name>`, значения JSON), чтобы Foundry стартовал уже с нужными значениями без
   перезагрузки.
2. **`init`/`setup`:** сверка — ключ применяется, только если настройка зарегистрирована
   (`game.settings.settings.has(...)`); незарегистрированные пропускаются с отметкой в HUD.
3. **`canvasReady`:** разрешение канваса, видео, модули.
4. **Постоянно:** контроллер адаптивного разрешения, FPS без фокуса, HUD.

### 4.2 Рычаги
| Рычаг | Механизм | Качество | Баланс | Картошка |
|---|---|---|---|---|
| Performance Mode | `core.performanceMode` (CONST.CANVAS_PERFORMANCE_MODES 0–3) | HIGH | MED | LOW |
| Макс. FPS | `core.maxFPS` | 60 | 60 | 45 |
| Разрешение канваса | рендер-разрешение PIXI (см. 4.3) | 100% | адапт. 70–100% | адапт. 55–85% |
| Масштаб под DPI | `core.pixelRatioResolutionScaling` | вкл | выкл | выкл |
| Анимация света | `core.lightAnimation` | вкл | вкл | выкл |
| Анимация зрения | `core.visionAnimation` | вкл | выкл | выкл |
| Мипмапы | `core.mipmap` | вкл | вкл | выкл |
| Видеофоны | управление `HTMLVideoElement` текстур | играют | пауза без фокуса | статичный кадр |
| Blur интерфейса | CSS-инъекция `backdrop-filter: none` | вкл | выкл | выкл |
| Sequencer | клиентская настройка модуля, если установлен | вкл | вкл | выкл |
| FXMaster | клиентская настройка модуля, если установлен | вкл | вкл | выкл |
| FPS без фокуса | переопределение maxFPS тикера при `blur`/`visibilitychange` | 60 | 15 | 10 |
| Prime Performance | его клиентские настройки, если модуль установлен | мягко | средне | агрессивно |

Точные имена ключей `core.*` и настроек модулей фиксируются на этапе проверки
осуществимости против реального v14 (перечень из `game.settings.settings`). Таблица —
целевое поведение; имена в столбце «Механизм» — рабочие гипотезы.

### 4.3 Адаптивное разрешение
- Контроллер — чистая функция `(state, frameTimeSample, now) → state`, с гистерезисом:
  если скользящее среднее времени кадра > цели × 1.15 в течение 2 с — шаг вниз (−5%);
  если < цели × 0.8 в течение 5 с — шаг вверх (+5%); границы из профиля; не чаще
  одного изменения в 1 с.
- Применение: изменение `resolution` рендерера PIXI с последующим `resize`, затрагивает
  только канвас; DOM-интерфейс Foundry остаётся чётким.
- Механизм применения — первая задача проверки осуществимости (spike). Запасной путь:
  переопределение `devicePixelRatio` до загрузки + фиксированный масштаб без адаптации.

### 4.4 HUD и «Замер»
- F9 — показать/скрыть HUD (FPS, мини-график, 1% low, мс/кадр, текущее разрешение,
  профиль), перетаскиваемый, позиция запоминается. Вид — ЖК-индикатор «Пульта».
- Shift+F9 — меню: смена профиля (применяется без перезагрузки для рычагов, где это
  возможно; для остальных — предложение перезагрузить), «Замер».
- «Замер»: 30 с автоматического панорамирования/зума по текущей сцене, запись avg FPS,
  1% low, min; результат в HUD и в телеметрию (`stats.json`).

## 5. Лаунчер — интерфейс «Пульт»

Направление: аппаратная панель / измерительный прибор. Светлая «дневная» панель
(`#D8D6D0`/`#E6E4DE`, графит `#2A2A28`, сигнальный оранжевый `#FF5A1F`, ЖК зелёный
`#B8F28A` на `#1E2A1E`) и «ночная» графитовая с тем же акцентом; по умолчанию — по теме
Windows. Шрифты: Archivo (интерфейс), Martian Mono (индикаторы, подписи) — локально, в бандле.

### 5.1 Экраны (одно окно, без модалок поверх модалок)
1. **Главный:** слоты серверов (A1, A2, …; светодиод статуса из `/api/status`; пустой
   слот — пунктир), кнопка «Запуск», ЖК (последний FPS сервера), ручка профиля
   КАЧ/БАЛ/КРТ, строка GPU.
2. **Настройка:** фейдеры (разрешение, макс. FPS, FPS без фокуса), переключатель Performance
   Mode, тумблеры остальных рычагов, пометка «изменено вручную» и «сброс к профилю»,
   строка движка (ANGLE, кэш). Глобально или для конкретного слота.
3. **Слот:** название, URL, свой профиль (или «как везде»), удалить.

### 5.2 Поведение
- Анимации только на CSS: ручка с фиксаторами, перекат цифр ЖК, проседание кнопок;
  отключаются при `prefers-reduced-motion`.
- «Запуск» закрывает окно лаунчера полностью (освобождение RAM), в трее остаётся
  иконка; закрытие игрового окна возвращает лаунчер.
- Safe mode: зажатый Shift при «Запуске» — без агента и со стандартными флагами.
- RU/EN: два JSON-словаря, по умолчанию язык системы.

## 6. Обработка ошибок
- Сервер недоступен / не Foundry → красный светодиод, запуск разрешён с предупреждением.
- Невалидный URL → ошибка у поля при сохранении слота.
- Потеря WebGL-контекста / отсутствие WebGL2 → агент сообщает в Rust (или отметка в
  store при следующем старте); при следующем запуске выбирается следующий ANGLE-бэкенд,
  на ЖК — понятная строка.
- Ошибка рычага → изолирована (try/catch на рычаг), остальные работают, отметка в HUD.
- Повреждённый store → бэкап `*.bak`, старт с пустыми значениями, сообщение на ЖК.

## 7. Тестирование
- Rust: юнит-тесты `profile`, `engine_flags`, миграций `store`, парсинга `/api/status`.
- Агент: Vitest; логика рычагов против заглушек `game`/`canvas`/`localStorage`; контроллер
  адаптивного разрешения — по TDD.
- Лаунчер: ручная визуальная проверка в превью браузера; проверка обеих тем и обоих языков.
- Натурные: пользователь прогоняет «Замер» на тяжёлой сцене во FLC-эквиваленте
  (безопасный режим Foundry Performance ≈ стандартный WebView2) и в профилях Foundry Performance на GTX 1060 и RTX 5070.
  Вход на сервер выполняет пользователь.

## 8. Риски
- Внутренности Foundry v14 (рендерер, видео-текстуры) могут отличаться от ожиданий →
  адаптивное разрешение и видео — первыми, как spike; есть запасные пути.
- Выдача одной команды Tauri удалённому origin может оказаться небезопасной/невозможной →
  телеметрия опциональна.
- Некоторые флаги Chromium в WebView2 игнорируются → проверка через `chrome://gpu`.
